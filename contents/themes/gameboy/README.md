# Game Boy theme

The sea as the original 1989 Game Boy (DMG) would draw it. Everything is generated by
`tools/gen-gameboy-theme.js` (run `node tools/gen-gameboy-theme.js`; `--check` is part of `npm test`).

## Emulated constraints

| DMG hardware | here |
|---|---|
| 4 LCD shades | exactly four colours in every texture: `#0f380f #306230 #8bac0f #9bbc0f`, the pea-green set used by DMG emulators (darkest ink to lightest "off" pixel). Nothing is blended or computed at run time. The one exception is the optional LCD-glass overlay (below). |
| 8x8 tiles | all art is cut from 8x8 tiles. The generator counts unique tiles (flips folded) and fails the build above DMG limits: OBJ <= 256, BG <= 256, both <= 384 (VRAM). Currently OBJ 96, BG 157. |
| OBJ sprites, 8x8 / 8x16 | metasprites of whole tiles: fish 16x8 (2 tiles), fry 8x8, newborn larva 8x8, angler 24x16, orca 32x16, jelly 16x16 and 8x16, worm 8x8, bubbles and sparkle 8x8, lure 8x8. |
| OBJ palettes: 3 shades + transparent | every sprite uses at most three shades (asserted at build and by `tests/gameboy-theme.test.js`). The five fish "colours" are shade patterns (dark with pale belly, two bars, spots, flank stripe, dithered back), not hues. |
| BG tile map | the water is dithered 8x8 tile rows (solid shades and 25/50/75 % ordered-dither ramps), the seabed a 64x14-tile map with sand, boulders, kelp and coral. |
| Palette registers (BGP/OBP) | the same art is stored once per register mapping as a small atlas: BG day / dusk / night fades (`bg-*.png`), OBJ normal / dimmed / inverted (`obj-n0/n1/i0.png`). Changing palette = picking another texture. |
| Scanline scroll (SCX per line) | the two water-surface rows scroll in opposite directions in whole-pixel steps from one 8 Hz tick; light rays and kelp frames use the same tick. |
| Integer-scaled LCD | the scene is a virtual screen of about 360 lines (640x360 on a 16:9 screen) scaled by a whole number of physical pixels (3x at 1080p, 2x at 720p, 6x at 4K); sprites sit on whole virtual pixels like OAM coordinates. |
| LCD pixel grid | one static tiled texture of faint dark lines between virtual pixels, only when the scale is a whole number of logical pixels. Set `lcdGrid: false` in `Scene.qml` to drop it. |

Deliberately not emulated: the 10-sprites-per-scanline limit (it would flicker) and the 40-sprite OAM cap.

## Behaviour

* **Day / night**: BGP fades (day, dusk/dawn, night) chosen from `daylight`; sprites keep their palette, so at night creatures glow against dark water, like a DMG night scene. `usesWaterColors` is false: the user's water colours do not apply.
* **Stress** (fish only): above 0.25 each fish flips to the inverted OBJ palette once the stress level passes its own fixed threshold, so the school turns gradually. Inverted fish tremble by +-1 virtual pixel (+-2 in alarm). Above 1.2 every fish flashes: half the school is inverted while the other half is normal, swapping every 400 ms (1.25 Hz, below the 2 Hz limit), so the screen as a whole never blinks.
* **Babies** are born as a 5x3 larva sprite that grows to fry size, with a two-frame sparkle tile above them while they spiral out.
* **Animation** is 3 drawn frames played 0-1-2-1 (tail beat, bell pulse, worm wiggle); a dying worm drops to the dimmed OBJ palette. The angler lure flickers through three lure tiles.

## Files

`Scene.qml` (virtual screen + LCD glass), `Ambient.qml` (tile-map background), `GBSprite.qml` / `EntityLayer.qml` (pooled delegates, shared atlas textures), `sync.js` (simulation -> sprites), `theme.js` (constants), `atlas.js` (generated rectangles), `img/` (generated atlases), `preview.png`.

Cost: about 40 static background items, one 8 Hz timer (stopped when `paused`), one `Image` per entity (plus a second only for the lure and sparkle), no animators, layers or shaders.
